# Roguelike 重构总案

> 本文是「COIN RUSH → Roguelike」就地改造的总纲：目标、边界、玩法骨架、战略原则、里程碑与引擎增件次序。
> 维护方式：讨论定案即回填本文；只写已批准的方向与次序，细节以代码与提交记录为准。

## 一、目标与边界

- **目标**：把 COIN RUSH（限时收币）就地改造为俯视角单屏 Roguelike（打怪升级生存）。
- **边界**：
  - **就地改造**，不新建仓库——复用现有外壳、场景框架、引擎子模块、测试与素材管线；
  - **main 冻结**：main 永远是历史基线，不再接受任何新提交；
  - **全部工作在 develop**：功能、修复、引擎升级均先落 develop；交付按 `develop → test → production` 单向流动（见 `docs/开发流程.md`）；
  - 引擎改动一律走「引擎仓提交 → 游戏仓子模块指针更新」的两仓舞蹈；引擎升级单独成笔提交，不与业务混提。

## 二、玩法骨架（已批准）

- **视角**：俯视角单屏（无滚动地图）。
- **操作**：WASD 移动（朝向跟随鼠标——面向指针一侧）；战斗为**鼠标瞄准·左键横扫**——攻击方向 = 玩家→鼠标，按住左键按 `attack_cooldown` 节奏连续横扫（单击挥一次、挥空也出招）；扇形判定（中轴=瞄准方向、张角 `attack_arc`、半径 `attack_range`）命中弧内**所有**怪物，各自结算伤害/飘字/微击退（`attack_knockback`）。
- **敌人**：从屏幕边缘刷新；三种变体（史莱姆 / 哥布林 / 骷髅，外观+数值分化）等权随机；持续增援；强度随局内时间增强。
- **成长**：击杀掉落经验宝石 → 拾取积累 → 升级；M1 升级自动加属性，M2 升级改为三选一卡牌。
- **结束**：HP 归零 → 结束结算；R 重开 / M 回主菜单。
- **存档**：由「最高分」升级为「最佳战绩」。

### 调整轮计划（M2 之前）

> 背景：M1 完成后依用户反馈进入调整轮（手感 → 世界/相机 → 怪物生态），方案已逐项批准。M2 三选一卡牌顺延至整轮之后。

**批一 · 手感快修**
- 刀锋同步命中：伤害改为随刀锋扫过程逐帧结算（不再出手瞬发整弧）；
- 扫程 0.15s → 0.10s，且改缓出曲线（快起慢收）；
- 残影轨迹（多重渐隐剑影）；
- 支点修正（挥剑锚点 / 轨道半径）。

**批二 · 世界与相机**
- 世界 3072×3072（4×4 区块，每区块 768×768、16×16 格 × 48px）；
- 含墙体 / 障碍：格级碰撞；玩家碰撞滑动；怪物绕墙先用轻量方案（不足再评估 A*）；
- 相机平滑跟随；
- 区块确定性生成（坐标哈希种子）、3×3 激活窗口、加载 / 卸载。

**批三 · 怪物生态**
- 巡逻 / 仇恨（~320px）/ 追击 / 栓绳（离巢 ~500px）/ 回巢；
- 头顶血条（受伤后显示）；
- 掉落 = 经验宝石 + 金币（局内货币储备）；
- 回巢回血 = 预留配置键（默认关闭）。

**收尾**：整轮合 test → 观星台验收（含战斗改版）→ M2 卡牌顺延其后。

## 四、战略原则（引擎成长观）

- **第一性原理**：引擎靠「新需求」长大，而非「打磨旧数据」——路径恒为「新玩法 → 新系统 → 新引擎件」。史实佐证：金币玩法逼出 Entity / Scene / Config；肉鸽战斗逼出 Input / Vec2 / 鼠标支持。
- **优化分类**：
  - **系统级优化**（玩法、怪物行为、界面、引擎级手感——粒子 / 震屏 / 输入延迟等）→ 喂引擎；
  - **数据级优化**（数值、节奏、素材换皮）→ 不喂引擎。
- **三条执行原则**：
  1. **成型优先**：整合（完整可玩 + 可发布）最能逼出引擎需求；2D 游戏求「成型」不求「完美」；
  2. **打磨择优**：只把系统级优化并入成型过程；纯数据打磨挂到封版之后；
  3. **3D 尽早**：2D 打磨过不了 3D 的门；2D 阶段使命 =「学做游戏 + 引擎测试场」，达成后应尽快跳 3D。
- **全程纪律**：保持「可玩、可回滚」——小步提交、每笔可构建可玩、里程碑验收。

## 五、引擎增件次序（与引擎 ROADMAP 对齐）

1. **Vec2 + 输入系统 + 实体增强**（已落地）：`engine/math/Vec2.h`（header-only）、动作映射 / 改键 / 边沿检测输入系统（键盘 + 鼠标两路绑定与指针位置）、Entity 增强（水平翻转 / 动画帧区间 / 最近邻采样）；
2. **粒子 + 相机震屏**（M3 拉动）；
3. **资源管理器**（纹理 / 字体统一加载与缓存）；
4. **3D 一跳（M5 拉动）**：渲染抽象层 + SDL_GPU 后端（按引擎 ROADMAP 红线二 / 三的姿势）。

> 次序原则：每项引擎件都由实际需求拉动（1 ~ 3 由 M1 ~ M4 拉动，3D 一跳由 M5 拉动），不提前做抽象（引擎 ROADMAP「游戏驱动、小步走」）。

### 引擎待办（驱动自 M1）

1. **Input**：增加「边沿挂起待消费」语义（高刷屏下更稳）；
2. **AudioSystem**：支持自定义音效注册（当前固定 6 种；升级音为游戏层 `LevelupSfx` 过渡实现）；
3. **单元测试**：未来迁回引擎仓（长远项）。

## 六、发布策略（摘要）

- 发布节点 = tag（`v0.x.y`）；打包脚本产出可运行 zip（本地归档，日后可传 GitHub Releases）；
- exe 与发布产物一律不入 git；分支职责与发布细则见 `docs/开发流程.md`。

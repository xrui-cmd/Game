# Roguelike 重构总案

> 本文是「COIN RUSH → Roguelike」就地改造的总纲：目标、边界、玩法骨架、战略原则、里程碑与引擎增件次序。
> 维护方式：讨论定案即回填本文；只写已批准的方向与次序，细节以代码与提交记录为准。

## 一、目标与边界

- **目标**：把 COIN RUSH（限时收币）就地改造为俯视角单屏 Roguelike（打怪升级生存）。
- **边界**：
  - **就地改造**，不新建仓库——复用现有外壳、场景框架、引擎子模块、测试与素材管线；
  - **main 冻结**：main 永远是历史基线，不再接受任何新提交；
  - **全部工作在 develop**：功能、修复、引擎升级均先落 develop；交付按 `develop → test → production` 单向流动（见 `docs/开发流程.md`）；
  - 引擎改动一律走「引擎仓提交 → 游戏仓子模块指针更新」的两仓舞蹈；引擎升级单独成笔提交，不与业务混提。

## 二、玩法骨架（已批准）

- **视角**：俯视角世界探索（世界 3072×3072 = 4×4 区块，相机平滑跟随玩家；含墙体与格级碰撞，无小地图）。
- **操作**：WASD 移动（朝向跟随鼠标——面向指针一侧）；战斗为**鼠标瞄准·左键横扫**——攻击方向 = 玩家→鼠标（经相机 screenToWorld 换算到世界坐标），按住左键按 `attack_cooldown` 节奏连续横扫（单击挥一次、挥空也出招）；扇形判定（中轴=瞄准方向、张角 `attack_arc`、半径 `attack_range`）命中弧内**所有**怪物，各自结算伤害/飘字/微击退（`attack_knockback`）。
- **敌人**：在玩家周围环带刷新（批二过渡版：550~750px 圆环内、激活区块、可走）；三种变体（史莱姆 / 哥布林 / 骷髅，外观+数值分化）等权随机；持续增援；强度随局内时间增强。
- **成长**：击杀掉落经验宝石 → 拾取积累 → 升级；M1 升级自动加属性，M2 升级改为三选一卡牌。
- **结束**：HP 归零 → 结束结算；R 重开 / M 回主菜单。
- **存档**：由「最高分」升级为「最佳战绩」。

### 调整轮计划（M2 之前）

> 背景：M1 完成后依用户反馈进入调整轮（手感 → 世界/相机 → 怪物生态），方案已逐项批准。M2 三选一卡牌顺延至整轮之后。

**批一 · 手感快修**
- 刀锋同步命中：伤害改为随刀锋扫过程逐帧结算（不再出手瞬发整弧）；
- 扫程 0.15s → 0.10s，且改缓出曲线（快起慢收）；
- 残影轨迹（多重渐隐剑影）；
- 支点修正（挥剑锚点 / 轨道半径）。

**批二 · 世界与相机**（已完成）
- 世界 3072×3072（4×4 区块，每区块 768×768、16×16 格 × 48px）；`world_chunks_x/y`、`world_seed` 可配（0 = 每局随机种子）；
- 含墙体 / 障碍：格级碰撞（世界边界一圈墙 + 每区块随机墙簇 / 短墙段；区块交界与出生保护区保证可通行）；玩家「分轴位移 + 撞墙滑动」；怪物碰撞滑动 + 卡住时轻量侧滑（完整绕墙 / 寻路留批三评估）；
- 相机平滑跟随（`camera_smooth_time` 指数平滑；进局 / 重开 snapTo，暂停 / 结束冻结）；实体与飘字渲染经相机换算、鼠标瞄准经 screenToWorld；
- 区块确定性生成（坐标哈希种子）、相机所在区块 ±1 激活窗口（烘焙区块纹理的加载 / 卸载，均有日志）、非激活区怪物暂停更新不删除；
- 怪物出生「过渡版」：玩家周围 550~750px 圆环内、激活区块、可走（批三大改前的可玩性保持）。

**批三 · 怪物生态**（已完成：状态机 / 血条 / 金币 / 生成正式版 / 绕墙轻量版）
- AI 状态机（`game/MonsterAi.h` 纯逻辑 + Monster 执行）：巡逻（绕巢游荡、半径 96px、间以 1~2s 停顿）→ 仇恨（玩家进入 320px）→ 追击（无时限，直到栓绳或死亡）→ 栓绳回巢（离巢 > 500px）→ 到巢恢复巡逻；回巢途中玩家「再入仇恨」立即重新追击（「再入」= 先离开仇恨圈、再回到圈内才成立——拉怪瞬间的贴身不算，否则与栓绳条件每步互相翻转、怪物原地抖动）；「攻击」不单列状态（接触伤害沿用，追击即贴身行为）；
- 生态配置键（`game.ini`，缺键回退）：`monster_patrol_radius=96` / `monster_aggro_radius=320` / `monster_leash_radius=500` / `monster_return_heal_percent=0`（回巢回血为**预留键**：逻辑完整，0 = 关闭默认不生效）；
- 生成规则正式版：怪物在**相机激活区块窗口内**随机 walkable 位置生成（离玩家 ≥ 500px）；**出生点即「巢」**（巡逻/栓绳圆心）；池 / 刷新节奏 / 难度曲线沿用；区块休眠时怪物暂停更新（批二行为验证不回归）；
- 头顶血条：受损后（hp < maxHp）头顶 40×5 小血条（深色底 + 红色按比例 + 描边、屏幕空间经相机换算），满血隐藏；
- 掉落扩展：击杀 = 经验宝石 + 金币（数量按变体：史莱姆 1 / 哥布林 2 / 骷髅 1）；**金币 = 局内货币**（拾取计数、HUD「金币: N」、restart 清零；本批只储备不消费——为商店/强化铺路）；**外观一眼可分**：金币 = 素材包原色，经验宝石 = 同源帧 R↔B 换道染成青蓝调（组装期染色，脚本 `Convert-SwapRedBlue`；乘法颜色调制无法把金色推成青蓝）；
- 绕墙轻量改进：卡死检测（0.5s 短窗口 实际/期望位移比 < 0.3）→ **持久化侧滑方向**（维持 1.2s、权重 1→0.35 线性衰减、窗口级重探/翻转）；**A\* 评估：轻量版实测可走出常见凹角/短墙段，A\* 暂不需要**（若后续反馈仍有滞留再立项）；
- 单测：`tests/monster_ai_test.cpp`（85 断言：转换边界含恰好等于半径、Return 到巢、回血 0 与百分比、Return 中重进仇恨含「再入」修正、池复用重置）。

**批四 · 三大问题修复**（已完成：碰撞解耦 / 怪物攻击 / 自动吸收与磁吸）
- **碰撞体积与视觉解耦**（引擎补件 + 游戏配置）：引擎 `Entity` 新增碰撞盒
  （`setCollisionBox(w,h,offsetX,offsetY)` / `collisionRect()` / `collisionRectAt()`；
  缺省 = 整张精灵、偏移 0——既有实体零行为变化；「判定/渲染解耦」纪律延续：
  `rect()` 仍是完整精灵盒供渲染/相机/血条用，物理用途一律走 `collisionRect()`）。
  游戏侧**脚部小盒**：玩家 32×26（宽居中、底部内收 4px、偏移 (8,54)）、
  怪物 36×30（宽居中、底部内收 6px、偏移 (6,12)）——取值为代码常量（可调，
  见 Player.h / Monster.h 常量块）。**物理迁移**：墙碰撞滑动、出生/落点校验
  （出生点/游荡点/击退候选）、玩家↔怪物触碰、怪物攻击距离全部改碰撞盒口径；
  精灵身体可自然叠压墙脚、脚盒不穿透；
- **怪物攻击逻辑与视觉（蓄力前扑，替换「纯接触即伤」）**：处于接触范围
  （碰撞盒触接 + 6px 余量）且冷却就绪 -> **蓄力 0.3s**（移速归零 + 沿反方向
  轻微后倾 4px；方向在出招瞬间朝玩家一次性锁定 = 躲避窗口）-> **前扑**
  （朝锁定方向短促前冲 10px / 0.1s，走碰撞滑动——视觉与逻辑同步）-> 结算：
  玩家仍在接触范围 = 命中（`monster_damage` 默认 10 + 玩家 0.8s 无敌沿用 +
  怪物回弹 40px（替换旧 150px 弹开）+ hit 音效）；已离开 = 落空。冷却新键
  `monster_attack_cooldown=1.2`（秒）；蓄力/前冲/回弹/脉冲/余量为代码常量
  （见 Monster.h 攻击常量块）。**视觉**：前冲位移 + 出招瞬时偏红染色脉冲
  0.1s（素材复用不加新图）；日志三态「怪物出招 / 怪物攻击命中 / 怪物攻击落空」
  （含变体名，蓄力落空即「玩家已离开」观测点）；
- **玩家↔怪物体积碰撞（不可重合与软分离）**：`World::slideMoveEx` 带「额外
  实心体」回调（原 `slideMove` 为无实心便捷包装）——玩家移动把**怪物盒当墙**
  （撞上滑停，类比撞墙滑动）、怪物移动把**玩家盒当墙**（追击/回巢/游荡/
  攻击动作全含）；**兜底分离**：任何来源（击退/瞬移）产生的怪物-玩家重叠，
  按最小分离量（MTV，`game/Separation.h` 纯函数）把**怪物**推出（玩家优先
  不动；被墙挤死的死角原地等下一帧）；**怪物↔怪物轻量软分离**：两两重叠
  按最小分离量各退一半（各自做墙/玩家校验，被挡的一侧少退不退）；
  **零分离向量防御**：完全重合时按 +x/+y 确定性回退、推出量加 0.01px
  亚像素余量（防「贴合被判重叠」死循环）；
- **经验自动吸收（宝石 homing）**：掉落即朝玩家飞——速度 700 起步、800px/s²
  加速、900 封顶（`game/Homing.h` 纯函数积分，抵达不过冲）；**飞行忽略墙体**
  （吸收是奖励结算的视觉化：玩家无需走动、穿墙可达，「掉落必有回报」不因
  地形打折）；与玩家脚盒重叠即 +10 经验（`grantXp` 沿用，含连升多级）；
  日志口径改「经验被吸收（进度 x/y，等级 N）」；
- **金币磁吸（保留实体拾取）**：新键 `coin_magnet_radius=140`（像素）——玩家
  中心进入即**磁化**（一次性、永久保持），朝玩家加速吸引（0 -> 800px/s，
  加速度 2000px/s²）、触及即拾取；**范围外静止不动**（仍可走过去拾取）；
  拾取日志沿用「拾取金币（本局累计 N）」；磁吸飞行同样忽略墙体；
- 单测新增两套：`tests/collision_homing_test.cpp`（55 断言：碰撞盒缺省/换算/
  非法尺寸忽略、最小分离四方向/贴合/重合防御/闭环、追踪速度与位移边界）+
  `tests/monster_attack_test.cpp`（33 断言：接触触发与边界、蓄力后倾、前扑
  净位移、Hit/Miss、冷却门控、池复用清态、零向量方向防御）；
- 引擎提交：`feat: 实体碰撞盒（碰撞体积与视觉解耦）`（引擎仓）+ 游戏仓
  子模块指针同步（chore 一笔）。

**收尾**：批四修复轮完成后整轮合 test → 观星台验收（含战斗改版与批四）→ M2 卡牌顺延其后。

### 调整批五A · 受击反馈与攻击动作（已完成：受击击退+红染 / 攻击升级 / 鼠标选卡）

> 背景：M2 交付后依用户反馈进入新调整轮——先做「受击反馈改版 / 怪物攻击
> 动作升级 / 升级卡鼠标选择」三项；「商店+法术」随后单独成批。

- **受击反馈改版（玩家/怪物同款）**：
  - 玩家受击（怪物攻击命中时）：**击退**——沿「怪物 -> 玩家」方向被推开
    （初速 480px/s 指数衰减、时间常数 0.11s、历时 0.18s、总位移约 42px；
    经碰撞滑动撞墙不穿墙；方向零向量退化回退向右）+ **输入抑制**（击退
    窗口内 WASD 移动输入被抑制约 0.18s，受击瞬间速度清零、窗口后从静止
    恢复）+ **红染**（0.3s，ADD 红光叠加——强度为绿蓝通道压到 60 的
    可调常量）；
  - **无敌闪烁（渲染跳隐）移除**：0.8s 无敌保留但静默（照旧防连续扣血，
    渲染不再有任何闪烁）——受击的可读反馈由「击退位移 + 红染」承担；
  - 怪物受击：白闪退役 -> **同款红染**（0.18s）+ 击退照旧；
  - 数值为代码常量（可调，见 Player.h / Monster.h 常量块）；

## 四、战略原则（引擎成长观）

- **第一性原理**：引擎靠「新需求」长大，而非「打磨旧数据」——路径恒为「新玩法 → 新系统 → 新引擎件」。史实佐证：金币玩法逼出 Entity / Scene / Config；肉鸽战斗逼出 Input / Vec2 / 鼠标支持。
- **优化分类**：
  - **系统级优化**（玩法、怪物行为、界面、引擎级手感——粒子 / 震屏 / 输入延迟等）→ 喂引擎；
  - **数据级优化**（数值、节奏、素材换皮）→ 不喂引擎。
- **三条执行原则**：
  1. **成型优先**：整合（完整可玩 + 可发布）最能逼出引擎需求；2D 游戏求「成型」不求「完美」；
  2. **打磨择优**：只把系统级优化并入成型过程；纯数据打磨挂到封版之后；
  3. **3D 尽早**：2D 打磨过不了 3D 的门；2D 阶段使命 =「学做游戏 + 引擎测试场」，达成后应尽快跳 3D。
- **全程纪律**：保持「可玩、可回滚」——小步提交、每笔可构建可玩、里程碑验收。

## 五、引擎增件次序（与引擎 ROADMAP 对齐）

1. **Vec2 + 输入系统 + 实体增强**（已落地）：`engine/math/Vec2.h`（header-only）、动作映射 / 改键 / 边沿检测输入系统（键盘 + 鼠标两路绑定与指针位置）、Entity 增强（水平翻转 / 动画帧区间 / 最近邻采样）、Entity 碰撞盒（批四：`setCollisionBox` / `collisionRect`——碰撞体积与视觉解耦）；
2. **相机**（批二拉动，已落地）：`engine/Camera.h`（header-only）——世界↔屏幕换算、指数平滑跟随、世界边界钳制；渲染链相机化（`Entity::render` 三参数，绘制处换算）；
3. **粒子 + 相机震屏**（M3 拉动）；
4. **资源管理器**（纹理 / 字体统一加载与缓存）；
5. **3D 一跳（M5 拉动）**：渲染抽象层 + SDL_GPU 后端（按引擎 ROADMAP 红线二 / 三的姿势）。

> 次序原则：每项引擎件都由实际需求拉动（1 ~ 4 由 M1 ~ M4 拉动，3D 一跳由 M5 拉动），不提前做抽象（引擎 ROADMAP「游戏驱动、小步走」）。

### 引擎待办（驱动自 M1）

2. **AudioSystem**：支持自定义音效注册（当前固定 6 种；升级音为游戏层 `LevelupSfx` 过渡实现）；
3. **单元测试**：未来迁回引擎仓（长远项）。

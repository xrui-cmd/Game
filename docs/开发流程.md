# 开发流程与分支规范

> 适用范围：游戏仓 GameDev（D:\GameProjcet\GameDev）。
> 核心原则：main 冻结、develop 开发、test 验收、production 发布；改动只沿 develop → test → production 单向流动。

## 一、分支职责

| 分支 | 定位 | 职责 |
| --- | --- | --- |
| `main` | 冻结基线 | 项目历史基线，自本规范生效起冻结，不再接受任何新提交 |
| `develop` | 开发主干 | 日常开发与 Roguelike 结构重构的主战场；功能、修复、引擎升级均先落在此分支 |
| `test` | 测试验收 | 待测版本验收；只接收 develop 合入，验收通过后方可向 production 传递 |
| `production` | 发布管理 | 唯一发布分支；只接收 test 合入；在此构建与归档可运行 exe 版本、打 tag |

## 二、合并流向

```
develop ──> test ──> production
```

- 逐步向上合并，**禁止反向合并**（test / production 一律不得合回 develop）。
- main 不参与任何合并，永远保持在冻结基线。
- 紧急修复同样先落 develop，验证通过后再向上传递，保持单一事实来源。

## 三、发布流程（草案）

1. develop 上功能完成并自测通过。
2. 验收通过 → `develop` 合入 `test`。
3. 测试通过 → `test` 合入 `production`。
4. 在 production 上以 `x64-release` 预设构建 release 版 `GameDev.exe`。
5. 打 tag：`v0.x.y`（x = 功能版本，y = 修订号）。
6. 用打包脚本产出可运行包，内容 = exe + 4 个 DLL + assets + config + 玩家说明：
   - `GameDev.exe`（游戏主程序）
   - `SDL3.dll`、`SDL3_image.dll`、`SDL3_ttf.dll`、`SDL3_mixer.dll`（4 个运行时动态库）
   - `assets/`（素材）、`config/`（配置）
   - 玩家说明（对外使用说明文档，待补充）

> 打包脚本尚未固化，暂以 CMake 构建产物目录（`out/build/x64-release`）为准；后续在 production 上补齐脚本与玩家说明。

## 四、引擎子模块注意

- 引擎仓：`D:\GameProjcet\GameEngine`，以 git 子模块挂载于 `libs/GameEngine`。
- 引擎仓提交新功能后，游戏仓在 **develop** 上执行以下命令更新子模块指针，然后提交：

  ```
  git submodule update --remote libs/GameEngine
  ```

- **升级引擎 = 一笔独立提交**，不与业务功能混提，便于按提交粒度回滚引擎版本。
